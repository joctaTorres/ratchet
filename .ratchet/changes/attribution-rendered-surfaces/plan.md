# attribution-rendered-surfaces

## Why

The model-failure attribution hint (stage, agent, exact model string, supplying scope) lives only in `StepResult.detail`, but every human-facing surface prints `blocker`/`message`: the non-JSON `batch apply` blocked line (`src/commands/batch/apply.ts` `renderResult`), the parked-step reason persisted and re-shown on resume (`persistStepOutcome`/`notAdvanced`), the journal entry (`engine.ts` records `message ?? blocker`), and the standalone change-step renderer (`src/commands/change-step-common.ts` `renderStepResult`). So a non-`--json` operator — including the generated apply-batch orchestrator skill — sees the pre-fix generic failure and never the hint. This is finding 1 (High) of the PR #95 review, and no test asserts the hint is displayed anywhere.

## What Changes

- The attribution branch of `mapSessionToOutcome` (`src/core/batch/engine/outcome.ts`) carries the hint in `blocker` and `message`, not only `detail`. That single mapper change threads the hint to all four rendered surfaces with no renderer edits (implements `features/attribution-rendered-surfaces/rendered-surfaces.feature`):
  - non-JSON `batch apply` blocked output — `renderResult` prints `result.blocker`;
  - parked-step reason shown on resume — `persistStepOutcome` parks `result.blocker`, `notAdvanced` re-shows `parked.reason`;
  - journal entry — `runChangeStep` records `outcome.message ?? outcome.blocker`;
  - standalone change-step renderer — `renderStepResult` prints `result.blocker`.
- `detail` keeps today's shape (hint above the truncated stderr tail), so `--json` consumers are unchanged (rendered-surfaces.feature, JSON scenario).
- Non-attributed failures — bare-name specs, failures after session journal progress, scope-less standalone runs — render byte-for-byte unchanged on every surface: only the attribution branch of the mapper changes (implements `features/attribution-rendered-surfaces/unchanged-rendering.feature`).
- The phase proof suite `test/batch-engine/model-failure-attribution.test.ts` gains rendered-surface assertions (stdout of the non-JSON renderers, parked reason, journal entry message), not only `result.detail` checks.
- Reference docs updated for the new surfaced shape: `docs/engine/overview.md` (failure-mapping section), `docs/commands/batch.md` (blocked/parked rendering), and the attribution sentence in `README.md`.

## Design

- **Fix at the outcome mapper, not the renderers.** The renderers print `blocker`/`message` for every failure, attributed or not. Making renderers additionally print `detail` would change the rendering of *non-attributed* failures (whose `detail` is the raw stderr tail) and violate the byte-for-byte requirement. Enriching the two fields inside the one branch that already gates on attribution (`input.modelAttribution && sessionEntries.length === 0`) confines the change to exactly the argv-rejection failure shape and reaches every present and future consumer of `StepResult` at once.
- **Field shapes.** In the attribution branch only: `blocker` becomes `` `Agent exited ${describeExit(spawn)} without reporting completion. ${hint}` `` and `message` becomes `` `Agent failed during ${transition}. ${hint}` `` (hint = existing `modelAttributionHint`, copy untouched — still guidance, never a diagnosis, agent-neutral). `detail` stays `hint\n\nstderrTail`. The hint therefore appears in both `detail` and `blocker`/`message` of the JSON result; that redundancy is deliberate — each surface reads one field.
- **Threading is already in place.** `toStepResult` (`context.ts:43`) maps `failed` → `blocked` preserving `blocker`; `persistStepOutcome` parks `result.blocker`; the journal write picks `message` first. No engine, park, or renderer code changes — this is the thinnest end-to-end slice for the phase goal. Stage coverage for `pr`/decompose spawns (finding 5) and the signal-kill gate (finding 6) are the sibling changes `pr-decompose-stage-attribution` and `signal-kill-hint-gate`, both `after` this one.
- **Testing standard (`testing` tag).** Unit layer: `test/batch-engine/outcome.test.ts` asserts the attributed mapping's `blocker`/`message` carry the hint and that bare-name/progressed/zero-exit mappings deep-equal today's output (pure mapper, no fs/spawn). Integration layer: `test/batch-engine/model-failure-attribution.test.ts` (the phase proof file) gains rendered-surface assertions over the tmpdir fixture — capture stdout (console spy) of the non-JSON render path for an attributed fast failure, assert the parked reason surfaced on the following run, read the journal entry written for the failed transition, and render an attributed result through the exported `renderStepResult`; the unchanged-rendering scenarios assert byte-for-byte equality of those same surfaces for bare-name, progressed, and scope-less standalone failures. Nothing new is pushed to the E2E layer — the surfaces are provable at unit/integration. Full suite and coverage gate stay green.
- **Documentation standard (`documentation` tag).** `docs/engine/overview.md` (~line 549) currently states the hint opens the failure `detail`; it must say the attributed failure's surfaced `blocker`/`message` — hence the rendered blocked line, the parked reason, and the journal entry — carry the hint too. `docs/commands/batch.md` parked/blocked rendering descriptions gain the attributed-failure sentence. `README.md` (~line 211) attribution sentence updated so it no longer implies the hint lives only above the stderr tail. No new Mermaid diagram: this extends existing failure-surface prose in docs that already carry the engine-flow diagrams; the flow's structure is unchanged.
- **Multi-agent standard (`multi-agent-support` tag).** The hint copy and the mapper are agent-neutral (the agent name is data, never special-cased); no generated skills/commands or per-agent surfaces are touched.
- **Delegated-lifecycle standard (`delegated-lifecycle` tag).** This change surfaces an orchestration outcome; it authors no lifecycle instruction text and adds no engine-local lifecycle semantics — the mapper/renderer split stays orchestration-only.
