# bound-protocol-buffers-and-align-cursors

## Why

The ReX streaming channels have three robustness holes (issue #90, confirmed OPEN and unfixed at decompose 2026-07-09 and re-verified against `main` today): all three partial-line buffers grow without bound (Node protocol buffer `rex-sidecar-runtime.ts:421`, sidecar partial `sidecar.py:318`, remote partial `rex-remote-runtime.ts:356`); the remote tail-poll cursor uses `Buffer.byteLength(chunk,'utf-8')` (`rex-remote-runtime.ts:361`) while the sidecar uses the exact `chunk.encode("utf-8","surrogateescape")` arithmetic (`sidecar.py:308`), so non-UTF-8 agent output can skew the remote cursor into duplicated/skipped output; and non-JSON protocol lines plus unknown event kinds are silently dropped (`rex-sidecar-runtime.ts:431`, `:414`), hiding sidecar bugs. Defensive fixes to failure paths; the happy-path contract is unchanged. Fixes #90.

## What Changes

- Partial-line buffers on all three channels are capped at 1 MiB; an oversized partial is flushed as a truncated stdout event instead of growing forever (`features/bounded-partials/flush-oversized-partial.feature`).
- A shared `surrogateEscapeByteLength` in the deduped runtime module `spawn-command.ts` replaces the remote runtime's `Buffer.byteLength` cursor arithmetic, counting surrogateescape lone surrogates (U+DC80–U+DCFF) as one byte each — exactly the sidecar's arithmetic; a shared `cursor-vectors.json` contract test locks the TS function and the Python `encode("utf-8","surrogateescape")` count together, and a remote-runtime test feeds non-UTF-8 (lone-surrogate) log content split across polls (`features/cursor-alignment/surrogateescape-byte-cursor.feature`).
- Non-JSON protocol lines and unknown event kinds are appended to the run's diagnostic transcript (the runtime's accumulated `stderr`, which flows into `AgentSpawnResult.stderr` and the mapped outcome detail) with a `[sidecar protocol]` prefix, instead of being dropped; outcome mapping is otherwise unchanged (`features/protocol-diagnostics/surface-non-json-frames.feature`).
- The sidecar's final drain emits interior blank lines exactly like the streaming loop (dropping only the empty segment after a trailing newline), unifying blank-line emission between stream and drain (`features/protocol-diagnostics/unify-blank-line-drain.feature`).
- No breaking changes: `AgentEvent` kinds, the sidecar protocol's known events, and `AgentSpawnResult` shapes are untouched; the sidecar's truncated-flush stdout event carries an extra `"truncated": true` field that existing Node consumers ignore.

## Design

**Shared cursor arithmetic (one implementation per language, contract-locked).** `spawn-command.ts` — the deduped runtime module from `dedup-rex-runtime-and-wire-ci` — gains `surrogateEscapeByteLength(s: string): number`: iterate code points; a lone surrogate in U+DC80–U+DCFF counts 1 byte (it encodes one original non-UTF-8 byte under surrogateescape), any other code point counts its standard UTF-8 length (1/2/3/4). The remote runtime's `drainTail` advances `offset` with this function instead of `Buffer.byteLength`. Why this is exact: swe-rex decodes log bytes with `errors="surrogateescape"`, JSON-escapes lone surrogates as `\udcXX`, and `JSON.parse` on the Node side preserves them — so the decoded string the remote sees carries each raw byte as one U+DC8x–U+DCFx code unit, and counting those as 1 byte reproduces the sidecar's `len(chunk.encode("utf-8","surrogateescape"))` exactly. The two implementations are locked together by `src/core/batch/engine/runtime/cursor-vectors.json` (`{ text, bytes }` pairs covering ASCII, multibyte, lone surrogates, mixed, split-multibyte tails, empty string), asserted by a TS test in `test/batch-engine/spawn-command.test.ts` and a `CursorContractTests` class in `test_sidecar.py` — the same pattern `shquote-vectors.json` already uses; the JSON is test-only and never ships in `dist/` (nothing new ships into consuming repos, per `generalizable-defaults`).

**Bounded partials (cap 1 MiB, flush-don't-drop).** `spawn-command.ts` exports `MAX_PARTIAL_BYTES = 1024 * 1024`; `sidecar.py` declares the same value with a cross-language sync comment (the arrangement `config.ts`/`sidecar.py` already use for pinned constants). Per channel:
- *Remote partial* (`rex-remote-runtime.ts`): after appending a chunk, if the held partial exceeds the cap, emit it as a stdout event (accumulating into `stdout` as usual), reset it, and append a one-line `[sidecar protocol] partial line exceeded 1 MiB; flushed truncated` note to the diagnostic transcript. Later bytes of the same long line simply start a new partial — content is never lost, only split at the cap boundary.
- *Sidecar partial* (`sidecar.py`): the current code pushes the partial back by decrementing `offset`, so a huge unterminated line is re-read and regrows every poll. When the trailing partial exceeds the cap, emit `{"event":"stdout","line":partial,"truncated":true}` and do NOT decrement the offset — the cursor advances past the flushed bytes and the next poll reads only new bytes.
- *Node protocol buffer* (`rex-sidecar-runtime.ts`): when `buf` exceeds the cap without a newline, flush it through the same protocol line handler as a complete line. An oversized protocol partial is by construction not a valid frame, so the flush lands in the non-JSON diagnostic path below — one mechanism, no second code path.
The TS caps compare UTF-16 code-unit length against the constant (code units ≤ bytes for the content in question; worst-case memory stays bounded at ~2 MiB per buffer), keeping the hot path free of repeated byte-encoding; the Python cap uses the encoded byte length it already computes.

**Surfaced protocol diagnostics.** In `rex-sidecar-runtime.ts`, the `catch { continue }` on `JSON.parse` becomes: append `[sidecar protocol] non-JSON line: <raw line>` to the runtime's `stderr` accumulator; the `default:` arm of `handleEvent` appends `[sidecar protocol] unknown event: <JSON.stringify(obj)>`. The accumulated `stderr` is the step's diagnostic transcript — it returns on `AgentSpawnResult.stderr` and `mapSessionToOutcome` already attaches it to the outcome detail — so a sidecar bug printing to stdout now surfaces in the recorded transcript without emitting an `error` event (which would wrongly force a failed outcome) and without polluting the agent's stdout transcript.

**Unified blank-line drain.** In `sidecar.py`, the final drain's `if line != ""` filter drops interior blank lines that the streaming loop emits. The drain adopts the streaming loop's exact split discipline: split on `\n`, pop the trailing `""` only when the content ends with a newline, emit every remaining segment (including interior blanks and a trailing partial, which at drain time is final and is emitted as its own line).

**Standards.** `testing`: every behavior above is proven at the unit layer — vitest fakes for both TS runtimes (canned `execShell`/child streams, no processes), stdlib `unittest` for `sidecar.py`, contract vectors read from the repo; test headers name the `.feature` they implement; full suite and coverage gate stay green. `documentation`: the docs task below is mandatory and blocking. `delegated-lifecycle`: this change touches only the runtime streaming seam — no lifecycle instruction text, prompt-builder, or done-rule is added to the engine; `multi-agent-support`: the runtime seam is agent-neutral and stays so (no agent-specific casing). Not security-remediation scoped: #90 is a robustness/debuggability issue, not a severe/high security exposure.
