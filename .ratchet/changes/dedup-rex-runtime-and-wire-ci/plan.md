# dedup-rex-runtime-and-wire-ci

## Why

The rex runtimes still carry duplicated logic that can silently drift: `buildRunCommand` (sidecar) and `buildRemoteRunCommand` (remote) are near-identical constructions, the Python `_shquote` in `sidecar.py` re-implements the shared TS `shquote` with no test tying them together, and `sidecar.py` re-declares the `python:3.12` image literal that `config.ts` already owns. Meanwhile `test_sidecar.py` never runs in CI, so sidecar regressions and a mis-packaged `sidecar.py` would ship unnoticed. This closes the remaining rex duplication from issue #91 (confirmed OPEN at decompose, 2026-07-09; phase-3 already extracted the shared TS `shquote` into `spawn-command.ts`). Fixes #91.

## What Changes

- One shared run-command builder in `src/core/batch/engine/runtime/spawn-command.ts` replaces the duplicated assembly in `buildRunCommand` / `buildRemoteRunCommand`; the two exported names stay as thin delegations so output is byte-identical and callers/tests are untouched (`features/rex-command-builder/shared-run-command.feature`).
- A shared shquote vectors file plus a TS (vitest) and a Python (stdlib unittest) contract test lock `shquote` and `_shquote` to identical quoting behavior (`features/shquote-contract/cross-language-vectors.feature`).
- The Python-side `DEFAULT_DOCKER_IMAGE = "python:3.12"` literal is removed; the sidecar's docker locus requires the `REX_IMAGE` env var Node always threads, and raises a clear error naming `REX_IMAGE` when it is unset instead of silently defaulting (`features/sidecar-image-default/defer-to-rex-image.feature`).
- `test_sidecar.py` runs in CI via a new `make test-sidecar` target and a ci.yml step, and `build.js` hard-fails (exit non-zero, not a warning) when `dist/core/batch/engine/runtime/sidecar.py` is missing after the asset copy (`features/sidecar-ci/sidecar-tests-in-ci.feature`).
- Behavior-preserving for every engine-driven path: Node always sets `REX_IMAGE` (`rex-bootstrap.ts:549`), so the only observable change is that a bare, mis-invoked sidecar now fails loudly instead of guessing an image.

## Design

**Shared command builder.** Add `buildAgentRunCommand(promptPath, request, opts?: { cwd?: string })` to `spawn-command.ts`, composing the existing `shquote`/`buildEnvExports` primitives into the full `[cd <cwd>; ]<exports>cat <promptPath> | <argv>` string. `buildRunCommand` (rex-sidecar-runtime.ts) and `buildRemoteRunCommand` (rex-remote-runtime.ts) become one-line delegations that keep their current names and signatures — the existing test suites (`rex-sidecar-runtime.test.ts`, `rex-remote-runtime.test.ts`, `permission-flags-in-argv.test.ts`) then double as the behavior-preservation proof, since they assert on the same outputs unchanged. This finishes what phase-3's `spawn-command.ts` extraction started: the runtimes keep zero private quoting/env/pipe assembly.

**Cross-language contract.** A single `shquote-vectors.json` lives next to the two implementations' tests' subject, at `src/core/batch/engine/runtime/`, listing `{ input, quoted }` pairs covering spaces, single quotes, double quotes, `$`, backticks, newlines, and the empty string. The TS side asserts in `test/batch-engine/spawn-command.test.ts`; the Python side adds a `ShquoteContractTests` class to `test_sidecar.py` resolving the file via `Path(__file__).parent`. Both read the same file — neither embeds a private copy, so a change to either implementation that breaks parity fails a test in that language. The JSON is test-only: `build.js` copies only non-test `.py` assets, so it never ships in `dist/` (consistent with `generalizable-defaults` — nothing new ships into consuming repos).

**Image-default drop.** `_make_deployment` in `sidecar.py` currently does `os.environ.get("REX_IMAGE", "").strip() or DEFAULT_DOCKER_IMAGE`. The constant and fallback go away: an unset/empty `REX_IMAGE` on the docker locus raises a `ValueError` whose message names `REX_IMAGE` as required, which the sidecar's existing top-level handler surfaces as a structured error event rather than a traceback. `config.ts` becomes the single declaration of `DEFAULT_DOCKER_IMAGE`; the cross-language "keep these in sync" comments in `config.ts`, `rex-bootstrap.ts`, and `sidecar.py` are updated to describe the new single-owner arrangement. Trade-off: a hand-launched sidecar without `REX_IMAGE` now errors instead of running `python:3.12` — accepted, since a loud error beats a silently drifted image and Node always threads the variable.

**CI wiring + packaging assertion.** The Makefile gains a `.PHONY: test-sidecar` target running `python3 src/core/batch/engine/runtime/test_sidecar.py` (stdlib-only — no pip, no venv, no Docker, per the test file's own design), plus a `help` line. ci.yml gains a step invoking `make test-sidecar` (ubuntu-latest ships python3). In `build.js`, the current warn-and-continue guard in `copyNonTsAssets` becomes an assertion that the exact packaged path `dist/core/batch/engine/runtime/sidecar.py` exists after the copy — the sidecar bootstrap resolves `sidecar.py` relative to the compiled module, so this is the one path that must hold; a miss now exits non-zero and fails the CI build step. The Makefile/ci.yml commands are this repo's own toolchain, not content shipped into user repositories, so naming `python3`/`make` here does not violate `generalizable-defaults`.

**Standards.** Per the `testing` standard, every new behavior is proven at the unit layer (vitest for TS, stdlib unittest for Python — no filesystem fixtures needed beyond reading the vectors file), test headers name the `.feature` they implement, and the full suite plus coverage gate stay green. Per the `documentation` standard, the reference doc task below is mandatory and blocking.
