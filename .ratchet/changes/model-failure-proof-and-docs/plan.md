# model-failure-proof-and-docs

## Why

The three sibling changes shipped the phase's machinery — per-stage scope resolution (`stage-scope-resolution`), the attributed failure surface with its integration suite (`attributed-failure-surface`), and doctor's spec-aware probing (`doctor-spec-awareness`) — but the phase gate has not been formally proven and the README, the primary user surface, still says nothing about the attributed model-failure hint: a user whose step fails fast under an explicit model has no README-level description of the failure they will see. This change closes the phase: it verifies the proof-of-work suite against the phase's success criteria and records it green, and completes the user-facing documentation.

Implements `features/model-failure-proof-and-docs/attribution-docs.feature`.
- `README.md`: verify the doctor sentence (`README.md:147`, added by `doctor-spec-awareness`) still matches shipped behavior — spec parsed, agent-part binary probed, model part never validated — correcting only on drift. Implements `features/model-failure-proof-and-docs/attribution-docs.feature`.

Implements `features/model-failure-proof-and-docs/attribution-docs.feature`.
- No production-code change expected: scope resolution, the attribution hint, and doctor probing are already shipped by the sibling changes. This change is the phase's proof and its user-facing documentation.

## Design

**Proof by verification, not re-authoring (per the `delegated-lifecycle` and `testing` standards).** Unlike Phase 1's proof-and-docs change, the proof suite already exists — `attributed-failure-surface` authored `test/batch-engine/model-failure-attribution.test.ts` as its own contract. This change's job is the phase gate: cross-check the suite's seven cases against the phase success criteria one by one and extend it only where a criterion is unproven, rather than duplicating a parallel suite. The suite drives `runChangeStep` over a tmpdir fixture (`fs.mkdtemp`, removed in `afterEach` — the fixture isolation pattern) with an injected fake spawn seam exiting non-zero and writing no journal entries, asserting on the surfaced step failure only — parser and scope-resolution internals stay proven at their unit layers (`test/core/batch/agent-setting.test.ts`, `test/core/batch/agent-scope-resolution.test.ts`) and are not re-tested here, per the test pyramid. Doctor's spec-aware probing is proven at the unit layer by `test/core/doctor/agent-spec-awareness.test.ts` (also shipped by its sibling); this change runs it as part of the closing full-suite check, but the phase proof-of-work command stays exactly `pnpm test test/batch-engine/model-failure-attribution.test.ts` as the manifest declares.

**"Unchanged" proven by comparison, not snapshot.** The suite's bare-name and progressed scenarios assert deep equality against the scope-less mapping's output rather than hardcoding today's failure text, so the "byte-for-byte unchanged" criterion cannot rot when unrelated changes legitimately alter the base failure surface. Verification keeps this property when extending the suite.

**Documentation (per the `documentation` standard — mandatory, blocking).** The README must describe the attributed failure hint in the same change that proves it: the hint is user-facing behavior (it changes what a failed step prints) and the README currently describes only the generic halt flow. The natural anchor is the `agent` setting paragraph (`README.md:211`) that already documents the `agent[:model]` spec — the hint is a property of configuring an explicit model, so it belongs beside the syntax, with a pointer to the engine Reference for the full mapping. The `docs/` Reference entries already exist (written by the siblings, per this repo's convention that a change documents what it ships); this change's doc task verifies each against shipped code and fixes drift rather than duplicating them. No new Mermaid diagram: the change adds no component or flow — the outcome-mapping and doctor docs it verifies sit inside existing documents whose diagrams are unaffected, and a new diagram would restate adjacent prose.

**Agent-neutral docs (per the `multi-agent-support` standard).** The README hint description names no specific agent: it describes the behavior for any configured `agent[:model]` spec, and doctor's probing is described over the supported-agent registry, never privileging one agent. Phrasing follows the manifest's locked decision — the hint is attribution plus "if this model id is invalid…" guidance, never a diagnosis and never stderr interpretation — so the docs must not imply ratchet detects invalid models.

**No shipped defaults touched (per the `generalizable-defaults` standard).** The change writes tests and docs in ratchet's own repo; nothing it produces ships into consuming repositories, and the proof command lives in the batch manifest, not in generated artifacts.
