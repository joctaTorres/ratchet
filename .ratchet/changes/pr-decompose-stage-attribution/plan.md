# pr-decompose-stage-attribution

## Why

The model-failure attribution hint (finding 5 of the PR #95 review) is threaded only into change-step contexts: `batch apply` passes `agentStageScopes` on `ResolvedStepContext` (`src/commands/batch/apply.ts:282`) and the engine builds a `ModelAttribution` only in `runChangeStep` (`src/core/batch/engine/engine.ts:362`). The batch-driven PR spawn (`runPrStepLocked`, routed through the `pr` stage) and the phase-decomposition spawn (`runDecompositionStepLocked`, scalar-resolved) get no attribution — so a `pr:`-stage or decompose fast-failure under an explicit model surfaces the pre-fix generic failure even though `pr` is a routable stage and `ModelAttribution.stage` is already typed as `StepKind`.

## What Changes

- `DecompositionStepContext` and `PrStepContext` (`src/core/batch/engine/contract.ts`) gain the same optional `agentStageScopes` field `BaseStepContext` already carries.
- `runPrStepLocked` captures the parsed `spec` its `buildSpawnRequest('pr')` call already returns, builds a `ModelAttribution` with `stage: 'pr'` and `scope = context.agentStageScopes?.pr` when the spec names a model and the scope is present, and passes it to `spawnAndMap` — so a `pr:` fast-failure gets the same attributed `blocker`/`message`/`detail` a change step gets (implements `features/pr-decompose-stage-attribution/pr-stage-attribution.feature`).
- `runDecompositionStepLocked` does the same with `stage: 'decompose'`; its scope comes from a new pure helper `uniformAgentScope` (`src/core/batch/config.ts`, beside `resolveAgentStageScopes`) that returns the supplying scope only when every stage entry is present and identical — the scalar-resolution counterpart for the stage-less decompose spawn (implements `features/pr-decompose-stage-attribution/decompose-stage-attribution.feature`).
- `batchApplyCommand` threads the already-resolved `agentStageScopes` into `runDecomposition`, `runPr`, and `runStackedPr` (new parameter each) and into the contexts they build; the "Left undefined for the decompose/PR/standalone paths" comment shrinks to the standalone path only.
- pr/decompose runs without an explicit model (bare name, stage-map-routed decompose falling to the default agent, scope-less contexts) surface byte-for-byte today's output — the mapper's existing `modelAttribution && sessionEntries.length === 0` gate is unchanged.
- The phase proof suite `test/batch-engine/model-failure-attribution.test.ts` gains pr-stage and decompose-stage attribution cases asserted on rendered surfaces, plus the unchanged shapes.
- Reference docs updated: the attribution prose in `docs/engine/overview.md`, `docs/commands/batch.md`, and the `README.md` attribution sentence now cover the pr and decompose steps.

## Design

- **Reuse the existing attribution seam end to end; add no new failure logic.** `ModelAttribution.stage` is already `StepKind` (`'pr'`/`'decompose'` fit), `modelAttributionHint` templates over any stage name, and `spawnAndMap` already accepts `modelAttribution` — the change-step path proves the whole pipe. The thin slice is: thread the scopes into the two remaining contexts and build the attribution at the two remaining spawn sites, mirroring the `runChangeStep` block (engine.ts:356-366) verbatim. The mapper, renderers, park, and journal paths are untouched — the sibling `attribution-rendered-surfaces` change already carries the hint through `blocker`/`message` to every rendered surface.
- **PR scope is the `pr` stage's scope.** The PR spawn resolves via `resolveAgentForStage(agent, 'pr')`, so its supplying scope is exactly `agentStageScopes.pr` — the same per-stage lookup `runChangeStep` does for its transition.
- **Decompose scope is the uniform scalar scope, derived honestly.** The decompose spawn resolves via `scalarAgent` (a stage map never routes it — it falls to the default agent with no model, so no attribution can arise). Whenever it has an explicit model, `settings.agent` is a scalar, and `resolveAgentStageScopes` materialized every stage to that scalar's scope. `uniformAgentScope(scopes)` encodes that invariant as a pure function — the single scope when all `AGENT_STAGE_KEYS` entries are present and identical, else `undefined` — rather than the engine reading an arbitrary stage key. It is gated behind `spec?.model !== undefined`, so a coincidentally-uniform map (which resolves no scalar spec) can never produce a false attribution.
- **CLI threads data it already holds.** `batchApplyCommand` destructures `agentStageScopes` from `resolveBatchSettings` today; passing it into the three helpers is pure parameter threading (`instruction-fed-config`: the engine still never re-reads config). Standalone paths stay scope-less by construction.
- **Testing standard (`testing` tag).** Unit layer: `uniformAgentScope` in `test/core/batch/config.test.ts` — uniform map → the scope, mixed/partial/empty/undefined → `undefined` (pure, no fs). Integration layer: the phase proof suite `test/batch-engine/model-failure-attribution.test.ts` gains — a pr-stage fast failure under `agent: {pr: 'opencode:zai/glm-5.2'}` with `agentStageScopes: {pr: 'manifest'}` asserting the hint (naming the "pr" stage and the batch manifest) in `blocker`/`message`/`detail`, the rendered blocked line, the parked reason, and the journal entry under the PR key; exactly one spawn carrying the exact model; a decompose fast failure under scalar `'opencode:zai/glm-5.2'` with uniform `'project'` scopes asserting the "decompose"-stage hint on the same surfaces; and unchanged shapes (bare-name pr spec, stage-map decompose, scope-less pr/decompose contexts) asserted byte-for-byte against today's output. PR fixtures mirror `test/batch-engine/pr-spawn-at-completion.test.ts` (batch dir created, `prGrouping: 'whole-batch'`, no prior PR journal); the test header names the implemented `.feature` files. Nothing pushed to E2E; full suite and coverage gate stay green.
- **Documentation standard (`documentation` tag).** The attribution prose currently scopes the hint to transitions: `docs/engine/overview.md` (session-to-outcome mapping, ~line 547) and `docs/commands/batch.md` ("Attributed fast failures", ~line 462) say "the transition's resolved spec"; `README.md` (~line 211) says "when a transition whose resolved spec explicitly names a model fails fast". All three are updated in this change to state the attribution also covers the batch-driven pr and decompose steps (pr scoped by its stage entry, decompose by the scalar setting's uniform scope). No new Mermaid diagram: this extends existing failure-surface prose in docs whose engine-flow diagrams are structurally unchanged.
- **Multi-agent standard (`multi-agent-support` tag).** The attribution stays data-driven and agent-neutral — agent and model names are opaque strings, no agent is special-cased, and no generated skill/command surface is touched.
- **Delegated-lifecycle standard (`delegated-lifecycle` tag).** Orchestration-only: the pr/decompose spawns keep delegating to `/rct:pr-open` / `/rct:decompose-phase`; no lifecycle instruction text and no done-rule is authored or altered.
