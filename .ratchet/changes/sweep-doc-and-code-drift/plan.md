# sweep-doc-and-code-drift

## Why

Issue #84 bundles accumulated doc/code drift and dead scaffold in the batch engine: docs describe `guidance` handling the code no longer performs, one batch owns two run directories (`run/` and `.run/`), and unreachable branches (`llm-judge` proof evaluation, the `phase-gated` StepState, the legacy `spawnerAsRuntime` fallback) mislead readers and reviewers. This change clears the bundle behavior-preservingly so the refactor-and-cleanup phase leaves the engine honest. Fixes #84.

## What Changes

Implements `features/engine-drift-sweep/doc-alignment.feature`, `run-dir-unification.feature`, and `dead-code-removal.feature`.

- Correct the `guidance` drift: `docs/engine/change-step.md` (field note ~line 42) still claims guidance is "appended verbatim to the agent instructions as an 'Additional guidance:' block"; the code hands it to the skill as `$ARGUMENTS` (`src/core/batch/engine/instructions.ts`). Doc is fixed to match code; code JSDoc (`contract.ts:105`) is already correct.
- Unify the batch run dirs: the ReX sidecar prompt dir moves from `.ratchet/batches/<batch>/.run/<id>/` to `.ratchet/batches/<batch>/run/<id>/`, the same directory that already holds the lock (`lock.ts:37`) and journal (`journal.ts:122`) and is already gitignored (`.gitignore:175`). The change-local `.ratchet/changes/<change>/.run/` directory is a distinct, intentional location and is untouched.
- Remove the unreachable `llm-judge` branch from `runProofOfWork` (`proof-of-work.ts:249`) plus its now-unused judge seam (`RunProofOfWorkDeps.judge`, `LlmJudge`, `JudgeRequest`, `JudgeVerdict`, the `judge-pass`/judge-only reasons) — `parseBatchManifest` rejects the kind at load, and the eval subsystem has its own independent judge machinery (`src/core/eval/judge.ts` builds on `realSpawner`/`resolveAdapter` directly, not on this branch). The manifest-level rejection with its actionable error stays.
- Remove the never-produced `phase-gated` StepState from the union (`contract.ts:221`) and from the docs (union listings and state tables in `overview.md`, `change-step.md`). **Consumer check recorded:** `nothing-ready` — listed alongside it in #84 — is now genuinely produced by the PR-step preconditions (`engine.ts:618,632`) and rendered by `apply.ts:294`, so it is kept, not removed; nothing about it changes, so no promotion to a separate issue is needed. `phase-gated` has zero producers and zero consumers beyond the type and docs.
- Remove the legacy `spawnerAsRuntime` fallback and the `spawner` field from the engine deps (`engine.ts:104,124,182`) — its JSDoc already marks it "preserved for one release" for unmigrated tests. All consumers are this repo's own tests; they migrate to injecting a `runtime`. The exported `Spawner` type and `realSpawner` are live (eval judge/harnesses) and remain exported.
- Annotate the two intentional identities instead of wiring them: `decompositionJournalKey` (`instructions.ts:255`) stays an identity function with JSDoc stating the identity is deliberate (the function exists as the single seam for the key derivation, so callers never inline the rule); the sidecar `spawnResult.signal: null` (`rex-sidecar-runtime.ts:283,364`) gains a comment stating the sidecar protocol conveys only an integer exit status, so the signal is intentionally null on this runtime and `describeExit`'s signal branch serves other runtimes.
- Relocate `docs/engine/coverage-gate.md` (CI machinery, not engine machinery) to `docs/coverage-gate.md` and update the README's link and published-site URL (`README.md:658-662`).

No breaking changes: every removal is of code with no producer or no external consumer, and the run-dir move relocates transient, gitignored scratch state.

## Design

**Behavior-preserving by construction.** Each item is either a doc correction, a deletion of code proven unreachable (checks recorded above), an annotation, or a rename of transient scratch paths. The one observable surface that moves — the sidecar prompt dir — is runtime scratch covered by an existing gitignore rule; no persisted state (journal, lock, state.json) changes shape or location.

**Consumer checks gate every removal** (per #84's rule: an item with a live consumer is promoted to its own issue, not changed). The checks performed at propose: `phase-gated` — no producer anywhere; `nothing-ready` — live producers found, so it is dropped from the removal list; `deps.spawner` — consumers are only in-repo tests; `LlmJudge`/`JudgeVerdict`/`JudgeRequest` — no consumer outside `proof-of-work.ts` and the index re-export (eval imports only `Spawner`, `BashRunner`, `evaluatePassCondition`, `realSpawner`, `realBashRunner`, `resolveAdapter`, `buildAgentSpawnRequest`). Apply re-verifies each check with a grep before deleting.

**Test migration stays mechanical.** The ~13 test files injecting `spawner` into engine deps switch to `runtime:` by wrapping their existing fake spawner with a small local adapter (the same replay logic `spawnerAsRuntime` performs today) placed in the tests' shared helper, so fake-agent behavior tables stay untouched. Per the testing standard this stays at the existing layers: engine tests remain integration-level over tmpdir fixtures; the run-dir move is asserted where the sidecar prompt-dir path is already unit-tested (`test/batch-engine/rex-sidecar-runtime.test.ts`); no check moves up the pyramid. Tests implementing a Scenario name the `.feature` in their header.

**Journal compatibility for removed reasons.** Proof-of-work journal entries persist `reason` as an opaque string; no read path compares against `judge-pass`, so removing judge-only members from the reason unions cannot break older journals (verified at apply with a grep over read paths).

**Docs move with the code in this change** (documentation standard): the engine Reference docs (`overview.md`, `change-step.md`, `agent-runtime.md:493`, `run-state.md` if it lists the batch run dir) are updated in the same change as each code edit, the coverage-gate page relocates, and the README's stale link is fixed. The overview's StepState Mermaid diagram (line 51) is held to the same accuracy bar as the prose.

Not applicable standards, checked and recorded: no skill/template/agent-facing surface changes (multi-agent-support, delegated-lifecycle, instruction-fed-config), no shipped defaults (generalizable-defaults), not a security exposure (security-remediation).
